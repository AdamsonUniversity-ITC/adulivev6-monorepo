# ABMS-RS-20260722-007 — Requisition Date Filter Layout

### Task ID

ABMS-RS-20260722-007

### Feature / Context

Shared ABMS Requisition Process filter panel.

### Objective

Keep the date-range controls fully contained within their filter card at all supported widths.

---

### Requirements

- Prevent native date inputs from overflowing or overlapping the date-range filter card.
- Preserve the existing date-range enable toggle and filter state behavior.
- Apply the correction through the shared filter panel for every requisition-process role.
- Keep both date inputs clearly identified.

---

### Acceptance Criteria

- From and To inputs remain inside the date-range card at narrow and wide layouts.
- The inputs do not overlap each other, adjacent cards, or the card boundary.
- Enabling, disabling, entering, and clearing the date range behaves as before.
- All role views using the shared filter panel receive the corrected layout.
- Targeted lint and the ABMS production build succeed.

---

### Inputs / Outputs (if applicable)

**Inputs:**

- Date-range enabled state and optional From/To dates.

**Outputs:**

- Responsive, bounded From and To date controls.

---

### Agent Assignment

- frontend_agent: Correct the shared date-range layout.
- qa_agent: Validate responsive containment, interaction behavior, lint, and build.
- reviewer_agent: Review shared-component impact and accessibility labels.
- project_manager: Maintain this task record.

---

### Dependencies

- Shared `FilterPanel` used by requisition-process role views.
- Browser-native date input rendering.

---

### Edge Cases

- Minimum card width generated by the auto-fit grid.
- Browser date inputs with large intrinsic widths.
- Disabled date-range controls.
- One date populated while the other is blank.
- Dark and light color schemes.
